ML-KEM Hybrid Migration and Implicit-Rejection Assessment

A public, third-party-rerunnable assessment of ML-KEM-512/768/1024 using pinned real implementations (liboqs 0.16.0, oqs-provider 0.12.0, system OpenSSL 3.0.13), classical baselines (X25519, P-256, P-384), and TLS 1.3-style hybrid key exchange (RFC 10024). Every measured claim connects to a runnable script and its unedited output.

Headline results

  • Sizes verified exactly: ML-KEM ek/ct match FIPS 203 Table 3 (512: 800/768; 768: 1184/1088; 1024: 1568/1568); X25519 32 bytes (RFC 7748).
  • Implicit rejection verified: 2100 tampered-ciphertext trials — decapsulation returned success 2100/2100 with a pseudorandom secret that never equalled the valid secret (0 accepted), deterministic 2100/2100. Control: 600/600.
  • Hybrid handshakes: X25519MLKEM768 19.3 ms mean vs X25519 16.83 ms (14.7% overhead); SecP384r1MLKEM1024 39.47 ms. Zero failures in 210 group handshakes.
  • Downgrade: 4/4 scenarios PASS.
  • Findings: 10 total — 4 Medium, 4 Low, 2 Info.

Headline finding

F-01 (Medium): there is no X25519 hybrid group for ML-KEM-1024 in RFC 10024 or oqs-provider 0.12.0 — category 5 pairs with P-384 only (SecP384r1MLKEM1024). See findings-report.md and findings.json.
